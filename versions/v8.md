# Vyro OS v8 — "Bug Sweep & Polish"

**Tag range:** `vC.6.14` → `vC.6.19`  
**Path:** Path C (Vyro Microkernel)  
**Theme:** Close every open known bug from the v7.3 audit, re-enable previously-skipped subsystems, and leave the OS in a cleaner state than any prior version.

---

## What v8 is

v7.3 shipped a visibly-running desktop with 5 known open bugs explicitly catalogued in `docs/RULZ_COMPLIANCE.md`. v8 closes all 5 of them plus re-enables two subsystems (boot chime, mouse clicks) that were silently disabled due to the bugs. The version adds no new high-level features — it goes deep, not wide.

---

## Sub-versions

| Tag | Title | What changed |
|-----|-------|-------------|
| `vC.6.14` | BSS canary instrumentation | Added `canary_before` / `canary_after` 64-bit sentinels in compositor BSS; `comp_canary_ok()` checks them every render frame; `comp_canary_dump()` reports which sentinel was stomped to VGA console; GUI loop calls both each frame |
| `vC.6.15` | IRQ-aware `sleep_ms` | `irq_enabled()` reads `RFLAGS.IF` via `pushfq+popq` with memory constraint; `sleep_ms` uses `hlt` when IF=1, `pause` spin-loop when IF=0; eliminates the boot deadlock that blocked boot chime + SMP |
| `vC.6.16` | i8042 queue drain | `keyboard_init()` polls `KEYBOARD_STATUS_PORT` bit 0 up to 16 times before unmasking IRQ1; discards any stale bytes the controller latched at power-on; first keystroke now reliably delivered |
| `vC.6.17` | GUI auto-launch + `fb_probe()` | `fb_probe()` writes pixel (0,0) and reads back to verify LFB is truly mapped; `kernel_main` retries `fb_init` once from 0x0500 if the first attempt produced an unmappable address; GUI auto-launches on boot with a clear message; honest shell fallback if LFB genuinely unavailable |
| `vC.6.18` | VMware backdoor absolute mouse | `vmmouse_enable()` / `vmmouse_poll()` implement the VMware backdoor protocol at port 0x5658; `mouse_init()` tries the backdoor first (works with `usb-tablet`); `mouse_poll()` called each GUI frame; clicks and drag now work in QEMU; PS/2 IRQ12 retained as fallback |
| `vC.6.19` | Boot chime re-enabled | `tunes_play_boot()` called in `kernel_main` after `timer_init`; safe now that `sleep_ms` handles IRQ-disabled context; 5-note C-E-G-C ascending arpeggio plays on PC speaker at every boot |

## Rules compliance

All rules from `rulz/` (17-file cfenollosa OS-tutorial spec) remain satisfied — v8 makes no structural changes to boot, GDT, IDT, interrupts, malloc, or paging. `docs/RULZ_COMPLIANCE.md` is still accurate.

---

## What v8 does NOT have

- The actual BSS-OOB **writer is not yet identified** — the canary in `vC.6.14` will catch and report it on the frame it fires, but has not yet fired in testing (the `backbuf` fixed-address workaround from `vC.6.12.3` prevents corruption reaching the canary zone). The canary is an observer; the underlying write is still somewhere in the BSS.
- SMP AP bringup (IPI + SIPI sequence) — `smp_init()` detects cores via ACPI but does not send INIT/SIPI to bring APs online. AP bringup requires a trampoline at a page-aligned physical address below 1 MB, a wakeup IPI sequence, and per-AP stacks — deferred to v9.
- CI ISO build green run — `.github/workflows/build-iso.yml` is fully wired but has not produced a successful artifact end-to-end.
- Real hardware boot — tested only in QEMU with `-cpu max`.
