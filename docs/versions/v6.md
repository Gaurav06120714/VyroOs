## What v6 is

v6 is the **honest audit release**. After v5 added hardware detection,
v6 sat back and asked: **what would it actually take to ship Vyro OS on
a real laptop?** The answer is documented in two new docs that don't
ship code — they ship *honesty*.

By the end of v6, the OS has:
- Same code capabilities as v5
- A comprehensive `AUDIT.md` cataloguing every gap
- A `ROADMAP_V6.md` with 4 tracks totaling ~116 person-months
- A `make usb` workflow that produces a real bootable image

v6 is the release that says "we are not done, here is the gap, here is
the time estimate" — calibrated honestly against the Asahi Linux project's
actual timeline.

### Roadmap V6 — 4 tracks

**Track A — Real PCs (~10 PM):**
- AHCI command list + FIS-based read/write
- NVMe Admin Queue + Identify + I/O
- E1000 DMA ring TX/RX (live Ethernet)
- RTL8169/8125 NIC driver
- xHCI Address Device + HID enumeration
- HD Audio (Intel HDA)
- ACPI AML interpreter (~8 PM)
- Intel iGPU mode setting (~12 PM)
- BIOS E820 / UEFI GetMemoryMap parsing
- True IRQ-driven preemption

**Track B — Apple Silicon (~48 PM ≈ 4 years, matches Asahi):**
- ARM64 architecture port
- Apple Silicon boot chain (m1n1 fork)
- AIC interrupt controller
- DART IOMMU (mandatory)
- Apple ANS2 NVMe protocol
- Apple AGX GPU (18+ months alone)
- DCP display, PMGR power, Broadcom WiFi, CS42L84 audio, etc.

**Track C — Userspace + Chromium (~46 PM):**
- Per-process virtual memory
- Linux syscall ABI emulation
- musl libc port
- Dynamic ELF linker
- POSIX shell, coreutils, package manager
- X11/Wayland compositor
- Mesa Gallium driver
- GCC port hosted on Vyro
- Chromium build

**Track D — Security (~12 PM):**
- KASLR, stack canaries, per-process page tables
- Apple Secure Boot signing pipeline
- Full-disk encryption, seccomp/sandbox
- Microcode update path

### Code carried forward from v5
All AHCI/NVMe/E1000/xHCI detection, HAL skeleton, ACPI walker, USB image
build — none of these were re-done, just polished and documented in
AUDIT.md.

## Honest deferrals at v6.0

The audit was honest about what v6 does NOT do:

1. Boot on Apple Silicon — needs full Track B (~48 PM)
2. Run Chromium — needs full Track C (~46 PM)
3. Production-grade security — needs full Track D (~12 PM)
4. Live Ethernet — needs E1000 DMA ring TX/RX (Track A item)
5. Real NVMe boot — needs NVMe Admin Queue + Identify + I/O (Track A item)
6. Real SATA boot — needs AHCI command list + FIS read/write (Track A item)

These deferrals were the LAUNCHING POINT for v7 — when this chat session
started, the user's handoff doc explicitly asked "what's pending, with
honest effort estimates" and the answer was AUDIT.md.
